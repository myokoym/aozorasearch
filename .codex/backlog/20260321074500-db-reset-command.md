# DB初期化コマンドの検討

## 背景

`load` の途中失敗で Groonga の DB が中途半端な schema のまま残ることがある。実際に `TermsMecab` が `default_tokenizer=nil` の壊れた状態で残り、DB ディレクトリを退避して再作成する必要があった。

## 目的

壊れた DB や空の DB を、安全に退避または再作成できる標準コマンドを用意する。

## 候補

- `bin/aozorasearch db:reset`
- `bin/aozorasearch db:backup-and-reset`
- `bin/aozorasearch reset-db`

## 検討項目

- 対象 DB パスを表示してから実行する
- 削除ではなく、まず日時付きバックアップへ退避する
- `--force` なしでは明示確認を要求する
- 空 DB 判定や壊れた schema 判定を自動化できるか確認する
- `AOZORASEARCH_HOME` を尊重する

## 受け入れ条件のたたき台

- 誤って本番相当 DB を即削除しない
- バックアップ先と復旧手順が表示される
- ローカル開発環境で再実行しやすい
